# Engineering Post-Mortem: Complete Problem & Solution Ledger (Tenda AC10 V1.0 — Hybrid OpenWrt 4.14.187)

This document records **every hardware, bootloader, kernel, RF, switching, networking, security, and operational problem** encountered during reverse engineering, porting, flashing, and live production hardening of the **Tenda AC10 V1.0** (`Realtek RTL8197FS-VE5` + `RTL8822BE` + `RTL8367RB-VB`), along with the exact root causes and permanent fixes baked into `build_hybrid_openwrt_ac10.sh` and `Configure_OpenWrt_ISP_WAN_and_WiFi.ps1`.

## Detailed Root-Cause & Fix Breakdown

### 1. Realtek Booter v3.4.11B.9: Delay-Slot Erasure Trap, UDP-Only Stack & WAN PHY Power-Down
1. **Multi-Segment `cs6c` Bootloader Self-Overwrite (`0x80001C2C`):** Inside `AutoBurn` (`0x800019D0`), register `$s7` holds the flash destination offset. When advancing to a second flash segment, the branch delay slot executes `move $s7, $s2` while `$s2 == 0`, resetting `$s7` to `0x00000000` and overwriting `mtd0`. Our builder packs kernel + SquashFS into a **single monolithic `cs6c` segment** at `0x00030000`, exiting cleanly before the buggy loop branch is ever taken.
2. **Why `ping 192.168.1.6` Never Replies:** Disassembly at `0x80001010` proves the bootloader checks `ip->protocol == 0x11` (`IPPROTO_UDP`) and drops everything else — ICMP Echo handling does not exist in ROM. Recovery tools detect readiness via ARP (`50:0F:F5:00:00:01`) and push directly to `192.168.1.6:69/UDP`.
3. **WAN Port Power-Down:** `0x8000ED48` invokes `rtk_port_phy_power_down(3)`, powering down the physical blue WAN jack during recovery. TFTP flashing must always use yellow `LAN 1–3` ports.

### 2. RTL8367RB-VB Switch Mapping & Odd-Port PVID Register Fix
Unlike D-Link DIR-842 R1 (even `Port 4` WAN), Tenda AC10 V1.0 routes physical WAN to **odd `Port 3`** and `LAN 1..3` to `Ports 2, 1, 0` (reset on `GPIO 58` / `&gpio1 26`). Upstream PVID initialization wrote odd-port PVID bits into `[15:0]` instead of `[31:16]`.
- `build_hybrid_openwrt_ac10.sh` applies **9 verified MIPS32 LE patches** to `vmlinux` (`0x8029A4DC..0x805084D4`) fixing VLAN membership (`LAN=0x107`, `WAN=0x108`), `GW_JACK_WAN=3`, `sll $a1, $a1, 16` upper-halfword PVID placement, and hardware L2 masks (`l2_mask_wan=0x08`, `l2_mask_lan=0x07`), plus a `+0x4000` `lzma-loader` `.data/.bss/_stack` relocation.

### 3. 5 GHz PCIe RTL8822BE: Blank OTP eFuse (`0xFF`), Skyworth SE5003L1 (`RFE Type 6`) & VHT20 Stability
Tenda left the `RTL8822BE` OTP eFuse completely unprogrammed (`0xFF`), causing stock `rtw88` to load `xtal_cap=0` (detuning the crystal and failing RF register `0x33` polling in `rtw8822b_config_trx_mode`) and `rfe_option=0` (`-17 dB` attenuation with external Skyworth `SE5003L1` PA/LNA bypassed).
- Solved by binary ELF patching `rtw88_8822b.ko` (`.rodata` + `.rel.rodata` relocations for `rfe_info[6]` / `rfe_defs[6]`, `rtw8822b_config_rfe_efem`, BB registers `0x82C/0x830/0x838/0x83C`), injecting per-unit `HW_WLAN0_11N_XCAP` & MAC via `/bin/set-mib.sh`, pinning `ifname='wlan1'` + PCIe path, and locking the default profile to **`VHT20` Channel 36 (`country='US'`, `23 dBm`)** for 0-drop, 0-retry operation.

### 4. Concurrent Wired + Wireless Datapath (`hwnat=0` + Software Flow Offloading + Cloned WAN MAC Poll)
1. **Eliminating the Bridged Wi-Fi Blackhole:** Keeping `dir842.asic.role='router'` and `fabric_autoreset=3` (`fabric_gw_rearm=1`) while defaulting `hwnat=0` + `firewall.@defaults[0].flow_offloading='1'` eliminates the ASIC NAPT blackhole on `br-lan` (`wlan1 -> eth0.1`) and delivers **~350–500 Mbps** across wired + Wi-Fi out of the box (with instant `echo 1 > /sys/module/rtl819x/parameters/hwnat` available for ~940 Mbps wired-only setups).
2. **Cold-Boot Cloned WAN MAC Synchronization:** `wait_netif_mac()` in `/etc/init.d/dir842-asic` now polls both `eth0.2` (`HW_NIC0_ADDR`) and `eth0.1` (`network.wan.macaddr`) before invoking `gw_prog`.

### 5. Apple RFC 9462 DDR Encrypted DNS & Shared-VLAN Socket Hardening
1. **Apple iOS / macOS:** Removing `ula_prefix`, disabling `ra`/`dhcpv6`, and advertising `dhcp_option '6,1.1.1.1,8.8.8.8,192.168.0.1'` enables transparent **HTTP/3 QUIC DoH** upgrades to `1.1.1.1:443` with zero iOS privacy warnings and zero IPv6 timeouts.
2. **WAN Socket Isolation:** `dnsmasq` `notinterface='eth0.1'` and `uhttpd` bound solely to `192.168.0.1:80` / `127.0.0.1:80` ensure zero listening sockets ever attach to the ISP WAN address.
