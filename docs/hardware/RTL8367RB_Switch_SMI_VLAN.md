# Realtek RTL8367RB-VB Switch SMI & VLAN Architecture

## 1. Executive Hardware Overview

The **Realtek RTL8367RB-VB** is a high-performance 5-port 10/100/1000M Gigabit Ethernet switch controller featuring an integrated low-power 5-port Giga-PHY, an embedded packet buffer, and a high-speed Extension Port supporting RGMII/MII interfaces.

On the Tenda AC10 V1.0 motherboard:
- The RTL8367RB manages all 4 physical RJ45 jacks on the router rear chassis (1 WAN port and 3 LAN ports).
- Communication between the main RTL8197FS SoC and the switch configuration registers is handled over a 2-wire Serial Management Interface (SMI) bit-banged via SoC GPIO pins.
- Data frame forwarding between the SoC GMAC0 and the switch occurs over a dedicated 1000 Mbps Full-Duplex RGMII bus connected to Switch Port 6.
- Hardware packet tagging utilizes Realtek's proprietary 8-byte CPU Tag to identify individual physical switch ports under Linux.

```
+-----------------------------------------------------------------------------------+
|                           Tenda AC10 V1.0 Switch Interconnect                     |
|                                                                                   |
|  +-------------------------+                     +-----------------------------+  |
|  |   RTL8197FS Host SoC    |                     |      RTL8367RB-VB Switch    |  |
|  |                         |   SMI (MDC / MDIO)  |                             |  |
|  |   GPIO 18 (Port C2) ----|====================>| MDC (Pin 44 / Clock)        |  |
|  |   GPIO 19 (Port C3) <---|====================>| MDIO (Pin 45 / Data)        |  |
|  |   GPIO 58 (Port H2) ----|====================>| RST_N (Hardware Reset)      |  |
|  |                         |                     |                             |  |
|  |   GMAC0 Controller      |   RGMII Bus         | Extension Port 1 (Port 6)   |  |
|  |   (Reg 0xBB804150=0x02) |<===================>| (1000 Mbps Full Duplex)     |  |
|  +-------------------------+  (Realtek 8-Byte    +-----------------------------+  |
|                                CPU Tagging)          |     |     |     |          |
|                                                      |     |     |     |          |
|                                                      v     v     v     v          |
|                                                    Port 0 Port 1 Port 2 Port 3    |
|                                                    (WAN) (LAN1) (LAN2) (LAN3)     |
+-----------------------------------------------------------------------------------+
```

## 2. SMI Bus Control via Bit-Banged GPIO Matrix

The RTL8367RB configuration registers are not memory-mapped directly into the CPU address space. Instead, all internal register reads and writes must pass through the Realtek proprietary Serial Management Interface (SMI), an I2C-like serial bus requiring precise microsecond timing.

### 2.1 Hardware Pinout & GPIO Allocations
Analysis of `vmlinux_stock.bin` (`plat_spi_init` at `0x806C0060` and `smi_init` at `0x801D7B10`) verifies the physical pin connections:

| SMI Signal | RTL8367RB Pin | RTL8197FS GPIO Pin | SoC Port & Bit | Virtual Register Addr | Direction / Electrical Characteristic |
|---|---|---|---|---|---|
| **MDC** | Pin 44 | **GPIO 18** | Port C, Pin 2 | `0x80594C10` | Output: Clock signal generated by SoC |
| **MDIO** | Pin 45 | **GPIO 19** | Port C, Pin 3 | `0x80594C1C` | Bi-directional: Data in / Data out |
| **RST_N**| Pin 63 | **GPIO 58** | Port H, Pin 2 | `0x80594C04` | Output: Active-Low hardware chip reset |

### 2.2 GPIO Pin Probe Configuration (`rtl819x_8367r_i2c_pin_probe` at `0x801DF888`)
In `vmlinux_stock.bin`, the kernel switch driver probes and allocates GPIO 18 (MDC) and GPIO 19 (MDIO) via `rtl819x_8367r_i2c_pin_probe` using standard kernel GPIO management:

```assembly
# Disassembly of rtl819x_8367r_i2c_pin_probe (vmlinux_stock.bin: 0x801DF888):
0x801df888:  addiu    $sp, $sp, -0x20
0x801df88c:  sw       $ra, 0x1c($sp)
0x801df890:  sw       $s1, 0x18($sp)
0x801df894:  sw       $s0, 0x14($sp)
0x801df898:  lw       $s1, 0x58($a0)        # Load platform data GPIO pin table
0x801df89c:  addiu    $a0, $a0, 0x10        # dev pointer
0x801df8a0:  lw       $a1, 0($s1)           # GPIO pin (18 MDC / 19 MDIO)
0x801df8a4:  addiu    $a2, $zero, 0x12      # GPIOF_DIR_OUT | GPIOF_EXPORT_DIR_FIXED
0x801df8a8:  jal      0x8016036c            # devm_gpio_request_one
0x801df8ac:  lw       $a3, 8($s1)           # GPIO label
0x801df8b0:  bltz     $v0, 0x801df8d4       # Check error return
0x801df8b4:  move     $s0, $v0
0x801df8b8:  lw       $v0, 4($s1)           # Active-low flag
0x801df8bc:  andi     $v0, $v0, 1
0x801df8c0:  beqz     $v0, 0x801df8d8
0x801df8c4:  move     $v0, $s0
0x801df8c8:  lw       $a0, 0($s1)
0x801df8cc:  jal      0x801623c8            # gpio_sysfs_set_active_low
0x801df8d0:  addiu    $a1, $zero, 1
```

**GPIO Driver Integration**: In the vendor kernel, GPIO pins 18 and 19 are requested via `devm_gpio_request_one` (`0x8016036c`), establishing directional control for SMI clock and data lines. OpenWrt target DTS must define these GPIOs under the switch MDIO bus node (`gpios = <&gpio0 18 GPIO_ACTIVE_HIGH>, <&gpio0 19 GPIO_ACTIVE_HIGH>;`).

### 2.3 Bit-Banged Protocol Waveform
The SMI protocol consists of:
1. **Preamble**: 32 consecutive clock cycles with MDIO held high (`1`).
2. **Start of Frame (SOF)**: 2-bit pattern `01`.
3. **Opcode**: `01` for Register Write, `10` for Register Read.
4. **Register Address**: 16-bit internal switch register address (MSB first).
5. **Turnaround (TA)**: 2 clock cycles for bus direction reversal.
6. **Data**: 16-bit register payload.

## 3. Physical Port Mapping & Booter Discrepancy

There is an important architectural distinction between port numbering in the **Realtek Bootloader (Stage 2)** versus the **Linux Kernel Runtime**:

### 3.1 Port Mapping Table
| Chassis Label | Physical Connector | Switch Silicon Port | Stock Kernel Mapping | Bootloader Disaster Mode State |
|---|---|---|---|---|
| **WAN** | Blue RJ45 Jack | **Port 0** | WAN Interface (`eth0.2` / `vlan2`) | Powered DOWN (`0x8000E90C`) |
| **LAN 1** | Yellow RJ45 Jack 1 | **Port 1** | LAN Interface (`eth0.1` / `vlan1`) | Active for TFTP Recovery |
| **LAN 2** | Yellow RJ45 Jack 2 | **Port 2** | LAN Interface (`eth0.1` / `vlan1`) | Active for TFTP Recovery |
| **LAN 3** | Yellow RJ45 Jack 3 | **Port 3** | LAN Interface (`eth0.1` / `vlan1`) | Active for TFTP Recovery |
| **N/A** | Internal (NC) | **Port 4** | Disabled / Isolated | Disabled |
| **N/A** | Internal (NC) | **Port 5** | Disabled / Isolated | Disabled |
| **CPU** | Internal RGMII Bus | **Port 6** | GMAC0 (`r8367_cpu_port = 6`) | CPU Host Uplink |

### 3.2 The Bootloader Port Isolation Mechanism
In `booter_stage2_v3.4.11B.9` at `0x8000ECE8`–`0x8000ED4C`:
- The booter explicitly isolates Port 3 (physical WAN) from the LAN forwarding mask.
- At `0x8000ED48`, it executes `rtk_port_phy_power_down(3)`, writing `0x1940` to PHY Control Register 0 of Port 3.
- **Operational Impact**: Connecting a recovery PC to the WAN port produces **no link carrier**. TFTP emergency recovery **must** be executed through physical LAN ports 1, 2, or 3.

## 4. Virtual LAN (VLAN) Architecture & Port Tagging

The RTL8367RB provides hardware 802.1Q VLAN filtering across 4096 VLAN IDs with wire-speed Layer 2 isolation.

### 4.1 Stock Firmware VLAN Matrix
In standard router operation, the switch segregates traffic into two primary broadcast domains:

```
+-----------------------------------------------------------------------------+
| VLAN ID | Description | Member Ports  | Untagged Ports | PVID Assignment   |
+---------+-------------+---------------+----------------+-------------------+
| VLAN 1  | Local LAN   | 1, 2, 3, 6    | 1, 2, 3        | Ports 1, 2, 3 = 1 |
| VLAN 2  | Internet WAN| 0, 6          | 0              | Port 0 = 2        |
+-----------------------------------------------------------------------------+
```

- **LAN Egress (Ports 1, 2, 3)**: Packets exiting LAN ports are stripped of 802.1Q tags before reaching client PCs.
- **WAN Egress (Port 0)**: Packets exiting to the ISP modem/fiber ONT are untagged (unless ISP VLAN tagging is explicitly enabled).
- **CPU Ingress/Egress (Port 6)**: Traffic flowing to the CPU incorporates Realtek CPU tagging.

## 5. Realtek 8-Byte CPU Tagging Structure

To allow the Linux kernel network stack to know which physical RJ45 port received a packet, the RTL8367RB prepends a proprietary **8-byte CPU Tag** immediately following the Destination MAC and Source MAC addresses of incoming Ethernet frames:

```
+-------------------+-------------------+-------------------+-------------------+
| Dest MAC (6 B)    | Source MAC (6 B)  | CPU Tag (8 B)     | EtherType (2 B)   | ...
+-------------------+-------------------+-------------------+-------------------+
```

### CPU Tag Format:
```
Byte 0..1: Realtek Protocol EtherType (0x8899)
Byte 2:    Flags & Priority:
           [7:5] Priority
           [4:0] Reserved / Sub-type
Byte 3:    Physical Port Mask / Ingress Port Index:
           [7:4] Reserved
           [3:0] Physical Port Number (0 = WAN, 1 = LAN1, 2 = LAN2, 3 = LAN3)
Byte 4..5: VLAN Protocol ID (0x8100)
Byte 6..7: 802.1Q TCI (VLAN ID & Priority):
           [15:13] 802.1p Priority
           [12]    CFI/DEI
           [11:0]  VLAN ID (1 for LAN, 2 for WAN)
```

In `vmlinux_stock.bin` (`RTL8367R_cpu_tag` at `0x801DB520`), the Linux network driver strips this 8-byte tag on ingress, assigns `skb->dev` to `eth0.1` or `eth0.2` based on Byte 3, and passes the clean Ethernet frame up the network stack.

## 6. RGMII Interface Timing & Delay Calibration

The high-speed data interconnect between SoC GMAC0 and RTL8367RB Port 6 operates according to the Reduced Gigabit Media Independent Interface (RGMII) Version 2.0 specification at 125 MHz clock frequency (Double Data Rate, yielding 1000 Mbps line rate).

### Critical Clock Skew Register (`0xBB804150`)
Because high-speed DDR signals suffer PCB trace delay differences, internal silicon delays must be calibrated to ensure setup and hold times are satisfied:
- Register Address: `0xBB804150` (Extension Port 1 Clock Delay Register).
- Calibrated Value: `0x02`.
- Timing Breakdown:
  - **Tx Delay**: 0.0 ns (SoC transmits data aligned with clock edge).
  - **Rx Delay**: 2.0 ns (SoC delays incoming receive clock by 2.0 ns to sample data in the center of the valid data eye).

**Hardware Consequence of Misconfiguration**: If register `0xBB804150` is left at default `0x00`, high-throughput gigabit transfers suffer CRC alignment errors, resulting in packet drops and capping throughput at ~300 Mbps instead of the theoretical 940 Mbps line rate.
