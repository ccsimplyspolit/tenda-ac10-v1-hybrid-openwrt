## 2. Развенчание мифа о памяти (Форензик-верификация)

В шапке профильной ветки 4PDA (пост #1) и ранних рекламных проспектах производителя заявлялись характеристики: *«Flash: 16 MB, RAM: 128 MB»*. Это вводило в заблуждение многих сборщиков прошивок, вызывая падения сборок из-за нехватки физической памяти.

Форензик-анализ реального железа и дампов памяти опровергает эти данные:
1. **Оперативная память (RAM):**
   - На плате физически **отсутствует отдельная внешняя микросхема DDR**.
   - Процессор маркирован как **`RTL8197FS-VE5`**. Суффикс **`S`** в номенклатуре Realtek означает **SiP (System-in-Package)** — кристаллы процессора и оперативной памяти объединены в одном BGA-корпусе.
   - Объем встроенной памяти составляет **64 МБ (512 Мбит) DDR2 SDRAM** (подтверждается логом инициализации контроллера памяти `0xB8001000` в `booter_stage2` и выводом ядра `MemTotal: 59328 kB`).
2. **Флеш-память (ROM):**
   - Установлена микросхема **Winbond W25Q64FV / W25Q64JV** (или полностью эквивалентная GigaDevice GD25Q64C).
   - Объем составляет ровно **8 МБ (64 Мбит / 8 388 608 байт)**, JEDEC ID `0xEF 0x40 0x17`.

## 3. Центральный процессор: Realtek RTL8197FS-VE5

- **Архитектура ядра:** MIPS 24KEc (совместимо с Lexra RLX5281), 32-битный Little-Endian (`mipsel`).
- **Тактовая частота:** 1.0 ГГц (1000 МГц).
- **Кэш-память:** 32 КБ L1 I-Cache (инструкции) + 32 КБ L1 D-Cache (данные).
- **Аппаратный NAT:** Специализированный ASIC-сопроцессор `TLU` (Table Lookup Unit), способный аппаратно транслировать и маршрутизировать до 1024 одновременных NAPT-потоков на скорости **940 Мбит/с** при нулевой загрузке центрального процессора.
- **Встроенное радио 2.4 GHz:** Аппаратный контроллер WMAC (`0x18640000`), поддерживающий 802.11b/g/n 2T2R со скоростью до 300 Мбит/с, подключенный к двум внешним антеннам через дискретные усилители Skyworth RFE Type 5.

### Карта физического адресного пространства SoC (MMIO)
Все встроенные периферийные контроллеры отображены в физическое пространство `0x18000000` (доступ через некэшируемый сегмент MIPS KSEG1 по базовому адресу `0xB8000000`):

| Физический адрес | KSEG1 виртуальный адрес | Периферийный блок | Описание |
|---|---|---|---|
| `0x00000000 - 0x03FFFFFF` | `0x80000000 / 0xA0000000` | DDR2 SDRAM | 64 МБ оперативной памяти |
| `0x18000000 - 0x18000FFF` | `0xB8000000` | System Control & WDT | Идентификатор чипа, делители частот, Watchdog |
| `0x18001000 - 0x18001FFF` | `0xB8001000` | Memory Controller | Тайминги и регистры автообновления DDR2 PHY |
| `0x18003000 - 0x180030FF` | `0xB8003000` | Reset Controller | Бит 10 регистра `0xB8003000` вызывает перезагрузку SoC |
| `0x18004000 - 0x18004FFF` | `0xBB804000` | GMAC0 & Hardware NAT | Дескрипторы DMA, FIFO кадров и регистры TLU NAT |
| `0x18004418` | `0xBB804418` | TLU_CTRL | Пауза/возобновление аппаратного конвейера трансляции |
| `0x18004D00 - 0x18004D2C` | `0xBB804D00` | TLU Table Access | Чтение и модификация аппаратной NAPT-таблицы `0x09` |
| `0x18005138` | `0xBB805138` | Pinmux Controller | Мультиплексирование выводов GPIO / SMI / SPI |
| `0x18143000 - 0x18143FFF` | `0xB8143000` | SPI Controller | Высокоскоростной контроллер SPI NOR Flash |
| `0x18147000 - 0x181470FF` | `0xB8147000` | UART0 | Основной последовательный порт консоли (115200 8N1) |
| `0x18B00000 - 0x18B00FFF` | `0xB8B00000` | PCIe RC0 Base | Конфигурация шины PCIe для радиомодуля 5 GHz |

## 4. Радиомодуль 5 GHz: Realtek RTL8822BE

- **Стандарт:** 802.11a/n/ac Wave 2 (2T2R, VHT80 до 866.7 Мбит/с, 256-QAM, MU-MIMO).
- **Интерфейс подключения:** PCI Express 1.1 x1, подключен к корневому комплексу SoC PCIe RC0 (`0x18B00000`, прерывание MIPS IRQ 5).
- **Аппаратные идентификаторы:** Vendor ID `10EC`, Device ID `B822`, Subsystem Vendor `10EC`, Subsystem ID `B822`.
- **Внешние усилители (FEM):** Два чипа **Skyworth RFE Type 6**, объединяющие малошумящий усилитель (LNA) на прием, усилитель мощности (PA) на передачу и антенный RF-переключатель T/R.
- **Опорная частота и кварц:** 40 МГц генератор с внутренней подстройкой емкостной нагрузки (`xcap = 27`).

### Аномалия чистой eFuse (Blank eFuse 0xFF)
В подавляющем большинстве сетевых карт заводские калибровки радиомодуля (мощность, базовые напряжения термометров, подстройка частоты кварца и MAC-адрес) записываются в однократно программируемую память чипа (OTP eFuse).
В Tenda AC10 V1.0 с целью удешевления производства **eFuse микросхемы RTL8822BE оставлена полностью чистой (все байты `0xFF`)**.

В коде драйвера Realtek HAL (`halmac_parse_efuse_data_88xx` по смещению `0x803725F4` в ядре) чистая eFuse детектируется как ошибка `HALMAC_RET_EFUSE_NOT_PROGRAMMED` (код возврата `5`). После этого драйвер `rtl8192cd` переходит в аварийный режим и ожидает инъекции калибровочных таблиц из раздела флеш-памяти `mtd1` (CFG) через ioctl `SIOCDEVPRIVATE` (`0x89F1`).
Если эти параметры не загружены (как происходит в стандартном `mac80211` OpenWrt), радиомодуль 5 GHz либо не поднимается вовсе, либо работает с минимальной мощностью (до 5–10 Мбит/с).

## 5. Гигабитный свитч: Realtek RTL8367RB-VB

Коммутатор RTL8367RB-VB обслуживает все 4 внешних порта RJ45:
- **Шина данных:** Подключен к контроллеру GMAC0 процессора по шине **RGMII (Extension Port 6)** на скорости 1000 Мбит/с Full Duplex. Для различения физических портов ядром Linux используется 8-байтный фирменный Realtek CPU Tag.
- **Шина управления (SMI):** Программирование регистров свитча выполняется программным дерганьем ножек (bit-banging) по двухпроводному протоколу SMI:
  - **MDC (Clock):** GPIO 18 (Port C, Pin 2).
  - **MDIO (Data):** GPIO 19 (Port C, Pin 3).
- **Аппаратный сброс (RST_N):** Пин сброса чипа свитча физически подключен к **GPIO 58** процессора.

### Физическая разводка портов свитча
| Порт свитча | Внешний разъем на корпусе | Роль в системе | VLAN на стоке | VLAN в OpenWrt |
|---|---|---|---|---|
| **Port 0** | **LAN 3** | Локальная сеть | VID 1 (LAN) | VID 1 (LAN) |
| **Port 1** | **LAN 2** | Локальная сеть | VID 1 (LAN) | VID 1 (LAN) |
| **Port 2** | **LAN 1** | Локальная сеть (TFTP) | VID 1 (LAN) | VID 1 (LAN) |
| **Port 3** | **WAN (Синий разъем)** | Подключение к провайдеру | VID 2 (WAN) | VID 2 (WAN) |
| **Port 6** | Внутренний линк к SoC | RGMII CPU Extension Port | Trunk (Tagged) | Trunk (Tagged) |

## 8. Схема распределения MAC-адресов в разделе калибровок (mtd1)

Заводской сектор калибровок расположен по физическому смещению **`0x00020000`** (размер 64 КБ). При редактировании дампа программатором (например, CH341A) базовый MAC-адрес устройства хранится в текстовом виде в формате ASCII:
- **Диапазон смещений базового MAC:** **`0x2086F` – `0x2087A`** (маркер переменной `HW_NIC0_ADDR=`).

Во время загрузки системы сетевым интерфейсам назначаются MAC-адреса по строгому правилу смещения от базового адреса:
1. **Интерфейс локальной сети (LAN bridge / eth0.2):** `Base_MAC + 0` (`HW_NIC0_ADDR`)
2. **Беспроводная сеть 2.4 GHz (wlan0):** `Base_MAC + 1` (`HW_WLAN1_WLAN_ADDR`)
3. **Интерфейс глобальной сети (WAN / eth0.1):** `Base_MAC + 2` (назначается смещение +2 для гарантированного исключения коллизий с Wi-Fi интерфейсом `wlan0`)
4. **Беспроводная сеть 5 GHz (wlan1):** `Base_MAC + 5` (`HW_WLAN0_WLAN_ADDR`)

> **Важно:** Загрузчик Realtek Booter и ядро Linux не проверяют контрольную сумму CRC32 раздела `mtd1`. Поэтому скрипт калибровки `set-mib.sh` в OpenWrt динамически ищет строку `HW_NIC0_ADDR=` и считывает MAC-адреса напрямую, что позволяет менять или восстанавливать адреса без пересчета контрольных сумм.
