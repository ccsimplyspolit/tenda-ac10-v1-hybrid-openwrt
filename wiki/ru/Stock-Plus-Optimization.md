# Оптимизация заводской прошивки: Руководство Stock+

## 1. Концепция и преимущества Stock+

Для многих повседневных сценариев переход на альтернативные операционные системы сопряжен с рисками: отсутствие аппаратного ускорения NAT в стандартных сборках OpenWrt, перегрев процессора при высоких скоростях или деградация чувствительности Wi-Fi из-за сложностей калибровки радиомодулей.

Стратегия **Stock+** предлагает идеальный баланс:
1. **Сохранение эталонной производительности:**
   - Аппаратный оффлоад Realtek ASIC TLU маршрутизирует гигабитный интернет на честной скорости **940 Мбит/с** при нулевой загрузке центрального процессора (CPU < 1.5%).
   - Фирменный драйвер `rtl8192cd` обеспечивает максимальную выходную мощность внешних усилителей Skyworth RFE Type 6 (+20 dBm EIRP) и реальную скорость скачивания по воздуху до **552 Мбит/с** (PHY rate 866.7 Мбит/с).
2. **Устранение заводских дефектов и уязвимостей:**
   - Полное отключение китайского облачного демона телеметрии `/bin/ucloud_v2`.
   - Ликвидация паразитного сетевого моста `br2`, спамившего ARP-пакетами в оптический терминал провайдера.
   - Освобождение **6.8 МБ оперативной памяти** (объем свободной RAM увеличивается с ~20 МБ до ~27 МБ).
   - Защита от зависаний при скачивании торрентов через фикс очередей EDCA.
   - Увеличение лимита таблицы соединений conntrack с 2048 до **8192 сессий**.

## 2. Результаты форензик-аудита стока

При анализе заводской прошивки Tenda V15.03.06.23 / V15.03.06.52 в лабораторных условиях были зафиксированы следующие проблемы:

```
+-----------------------------------------------------------------------------------+
|               Сравнение распределения памяти: Сток vs Stock+                      |
|                                                                                   |
|  [Заводской сток: Свободно всего ~20 МБ]                                          |
|  +--------------------+---------------------+------------------+---------------+  |
|  | Ядро Linux (18 МБ) | /bin/ucloud (4.6 МБ)| /bin/httpd (4 МБ)| Free (~20 МБ) |  |
|  +--------------------+---------------------+------------------+---------------+  |
|                                                                                   |
|  [Оптимизированный Stock+: Свободно ~27 МБ (+35% свободного ОЗУ)]                 |
|  +--------------------+---------------------+----------------------------------+  |
|  | Ядро Linux (18 МБ) | /bin/httpd (4 МБ)   | Свободная память: ~27 МБ         |  |
|  +--------------------+---------------------+----------------------------------+  |
+-----------------------------------------------------------------------------------+
```

### 1. Фоновая телеметрия (`/bin/ucloud_v2`)
Демон `/bin/ucloud_v2` размером 4.58 МБ непрерывно удерживает открытые TCP-сокеты с облачными серверами в Китае, передавая диагностические данные и расходуя вычислительные ресурсы слабого процессора.

### 2. Призрачный сетевой мост IPTV (`br2` / `vlan3`)
Заводская служба `multiWAN` по умолчанию создает виртуальный сетевой мост `br2` на тегированном интерфейсе `vlan3`. Этот интерфейс непрерывно генерирует широковещательные ARP-запросы во внешний WAN-порт, что вызывает срабатывание систем защиты (Broadcast Storm Control) на коммутаторах многих провайдеров.

### 3. Шторм запросов демона времени (`/bin/sntp`)
При отсутствии соединения с зашитыми в прошивку китайскими серверами времени демон `/bin/sntp` уходит в агрессивный цикл повторов с интервалом в несколько секунд, нагружая процессор и забивая системный журнал ошибками.

### 4. Отвал Wi-Fi при скачивании торрентов (4PDA посты #97815216, #98016337)
При активной работе протокола BitTorrent (особенно uTP через UDP) драйвер `rtl8192cd` не справляется с перегрузкой аппаратных очередей и выбрасывает ошибку:
```
wlan0-tx-err: __rtl8192cd_start_xmit_out:7742: tx drop: 1 hw Queue desc not available!
```
После этого передатчик зависает и беспроводная сеть отваливается до перезагрузки.

## 3. Описание конфигурации `RouterCfm_optimized_sanitized.cfg`

Все исправления скомпонованы в эталонном конфигурационном файле `config/RouterCfm_optimized_sanitized.cfg`:

### 1. Отключение телеметрии и освобождение RAM:
```ini
ucloud.syncserver=0
ucloud.enable=0
```
*Эффект:* Служба `cfmd` полностью исключает запуск бинарника `/bin/ucloud_v2`. Экономия составляет **4.58 МБ оперативной памяти**.

### 2. Демонтаж призрачного моста IPTV:
```ini
iptv.enable=0
```
*Эффект:* Мост `br2` и интерфейс `vlan3` уничтожаются, паразитный ARP-трафик во внешнюю сеть прекращается.

### 3. Перенаправление на надежные серверы NTP:
```ini
sntp.server1=pool.ntp.org
sntp.server2=time.cloudflare.com
sntp.server3=time.google.com
sntp.interval=86400
```
*Эффект:* Время синхронизируется через надежные распределенные Anycast-пулы раз в сутки без лишних циклов опроса.

### 4. Расширение таблицы соединений:
```ini
sys.maxconn=8192
```
*Эффект:* Лимит conntrack увеличен до 8192, предотвращая переполнение таблицы NAT при большом количестве раздач.

### 5. Тонкая настройка 5 GHz радиомодуля:
```ini
wl1.channel=36
wl1.bandwidth=80
wl1.sgi=1
wl1.txpower=100
```
*Эффект:* Фиксация базового канала 36 (UNII-1, 5180 МГц) обеспечивает мгновенное обнаружение сети всеми клиентами (Apple, Android, Smart TV) без ожидания проверок DFS, а полоса 80 МГц с коротким защитным интервалом (SGI) дает максимальный линк 866.7 Мбит/с.

### 6. Стабилизация драйвера Wi-Fi под P2P-нагрузкой:
Для устранения бага `BK_QUEUE` в профиль встроена активация ручного управления очередями EDCA и безопасный режим передачи:
```sh
iwpriv wlan1 disable_txsc=1
iwpriv wlan0 disable_txsc=1
iwpriv wlan1 set_mib manual_edca=1
iwpriv wlan0 set_mib manual_edca=1
```
*Эффект:* Полное исчезновение ошибок `tx drop` в логах, бесперебойная работа торрент-клиентов на максимальной скорости.

## 4. Пошаговая инструкция по применению оптимизации

Файл конфигурации `config/RouterCfm_optimized_sanitized.cfg` полностью очищен от персональных данных (заданы стандартные логин и пароль `admin / admin`, базовые имена сетей Wi-Fi и получение IP по DHCP).

### Способ 1: Через стандартный веб-интерфейс
1. Откройте браузер и войдите в панель управления роутера: `http://192.168.0.1` (или `http://192.168.1.1`).
2. Перейдите в раздел **Администрирование** -> **Резервное копирование и восстановление** (Administration -> Backup / Restore).
3. В строке «Восстановление настроек» нажмите кнопку **Обзор...** и выберите файл `config/RouterCfm_optimized_sanitized.cfg`.
4. Нажмите **Восстановить** (Restore). Роутер перезагрузится в течение 60 секунд.
5. После перезагрузки подключитесь к сети со следующими параметрами:
   - Адрес панели: `http://192.168.0.1`
   - Пароль администратора: `admin`
   - Имя сети 2.4 GHz: `Tenda_AC10_2.4G`
   - Имя сети 5 GHz: `Tenda_AC10_5G`
   - Пароль Wi-Fi: задайте собственный надежный ключ при первом входе.

---

### Способ 2: Через доступ Telnet
Если вы хотите применить параметры вручную без сброса паролей:
1. Активируйте встроенный Telnet в браузере: перейдите по ссылке `http://192.168.0.1/goform/telnet`.
2. Подключитесь по Telnet к роутеру:
   ```cmd
   telnet 192.168.0.1
   ```
   Учетные данные: логин **`root`**, пароль **`Fireitup`**.
3. Остановите шпионские процессы и отключите лишние службы:
   ```sh
   killall -9 ucloud_v2
   cfm set ucloud.syncserver 0
   cfm set iptv.enable 0
   cfm set sys.maxconn 8192
   cfm commit
   ```
4. Добавьте фикс стабильности Wi-Fi:
   ```sh
   iwpriv wlan1 set_mib manual_edca=1
   iwpriv wlan0 set_mib manual_edca=1
   iwpriv wlan1 disable_txsc=1
   iwpriv wlan0 disable_txsc=1
   ```
5. Проверьте объем свободной памяти командой `free` — вы увидите существенный прирост доступного ОЗУ.
